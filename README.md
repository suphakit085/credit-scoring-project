# Credit Scoring Project

ระบบประเมินความน่าจะเป็นที่ผู้ขอสินเชื่อจะผิดนัดชำระ จากชุดข้อมูล Home Credit
Default Risk มีขั้นตอนเทรนที่ป้องกัน data leakage, probability ที่ผ่าน
calibration และหน้าเว็บ Streamlit สำหรับเจ้าหน้าที่สินเชื่อ

> ระบบนี้เป็นงานตัวอย่างด้าน Machine Learning ไม่ควรใช้อนุมัติหรือปฏิเสธสินเชื่อ
> จริงโดยไม่มีการตรวจสอบด้านกฎหมาย ความเป็นธรรม data governance และ human review

รายละเอียดทุกขั้นตอนอยู่ใน [PROJECT_WORKFLOW.md](PROJECT_WORKFLOW.md)
สถานะข้อมูลและวิธีกู้คืนอยู่ใน [DATA_RECOVERY.md](DATA_RECOVERY.md)

## ผลลัพธ์

วัดบน validation 30,752 แถวที่ไม่เคยถูกใช้ฝึกหรือปรับแต่งโมเดล
ช่วงเชื่อมั่นมาจาก bootstrap 2,000 รอบ

| Metric | ค่า | ช่วงเชื่อมั่น 95% |
|---|---:|---|
| ROC-AUC | 0.76 | 0.755 ถึง 0.774 |
| Average precision | 0.24 | 0.226 ถึง 0.259 |
| Brier score | 0.068 | 0.065 ถึง 0.070 |
| Precision ที่เกณฑ์ตัดสิน | 0.27 | 0.251 ถึง 0.281 |
| Recall ที่เกณฑ์ตัดสิน | 0.36 | 0.339 ถึง 0.378 |
| สัดส่วนผู้สมัครที่ถูกตีธง | 10.9% | 10.5% ถึง 11.2% |

เส้นฐานของ average precision คือ 0.081 ซึ่งเท่ากับอัตราผิดนัดในข้อมูล
โมเดลจึงจับผู้ผิดนัดได้ดีกว่าการสุ่มราวสามเท่า

Calibration ผ่านการทดสอบ ทั้ง 10 กลุ่มมีค่าทำนายอยู่ในช่วงเชื่อมั่นของอัตรา
ผิดนัดจริง และ Hosmer-Lemeshow p เท่ากับ 0.43

ตัวเลขทั้งหมดมาจาก validation split เดียว จึงรายงาน ROC-AUC สองตำแหน่ง
การเขียนสี่ตำแหน่งเป็นความแม่นยำเทียมเมื่อช่วงเชื่อมั่นกว้าง 0.019

## หลักการออกแบบที่สำคัญ

**โมเดลเรียนรู้เฉพาะสิ่งที่หน้าเว็บเก็บได้จริง** โมเดลรุ่นแรกใช้ 495 คอลัมน์
รวมประวัติเครดิตบูโรที่หน้าเว็บไม่เคยได้รับ ตอนใช้งานจริงฟีเจอร์ 137 จาก 200 ตัว
จึงถูกตรึงที่ค่ามัธยฐาน เมื่อเทียบบนแถวเดียวกัน 23,091 แถวด้วย paired bootstrap

| โมเดล | ROC-AUC |
|---|---:|
| รุ่นแรก 495 คอลัมน์ เมื่อมีข้อมูลครบ | 0.776 |
| รุ่นแรก ในสภาพที่หน้าเว็บใช้งานจริง | 0.761 |
| รุ่นปัจจุบัน 20 ช่องจากฟอร์ม | 0.765 |

รุ่นปัจจุบันชนะรุ่นแรกในสภาพใช้งานจริง 0.004 ช่วงเชื่อมั่น 0.001 ถึง 0.008
และแพ้รุ่นแรกในกรณีที่มีข้อมูลครบ 0.011 ช่วงเชื่อมั่น 0.006 ถึง 0.015
ทั้งสองผลมีนัยสำคัญ การจำกัดขอบเขตจึงดีกว่าในสภาพที่ใช้งานจริง
และมีต้นทุนจริงเมื่อเทียบกับกรณีที่มีข้อมูลครบ

**ไม่ใช้เพศและสถานภาพสมรส** เดิมผู้สมัครที่ข้อมูลเหมือนกันทุกช่อง ต่างกันแค่เพศ
ได้ PD ต่างกัน 1.45 เท่า การตัดสองตัวแปรนี้ออกเสีย ROC-AUC 0.0017 ซึ่งแยกไม่ออก
จากศูนย์ทางสถิติ อายุยังคงไว้ เพราะการตัดออกเสียความแม่นยำอย่างมีนัยสำคัญ
และหลายประเทศอนุญาตให้ใช้ภายใต้เงื่อนไข ควรตรวจกับหลักเกณฑ์ของผู้กำกับดูแล
ในประเทศก่อนนำไปใช้จริง

**เกณฑ์ตัดสินมาจากต้นทุน** เกณฑ์คือ 1 หารด้วย (1 + R) โดย R คือความเสียหาย
ของการอนุมัติผู้ที่จะผิดนัด เทียบกับการปฏิเสธผู้ที่จะชำระคืนได้ ค่าเริ่มต้น R = 5
ได้เกณฑ์ 16.67% ปรับได้ด้วย `--cost-ratio`

| R | เกณฑ์ | ตีธง | Precision | Recall |
|---:|---:|---:|---:|---:|
| 3 | 25.0% | 6.3% | 0.32 | 0.25 |
| 5 | 16.7% | 10.9% | 0.27 | 0.36 |
| 8 | 11.1% | 19.4% | 0.22 | 0.53 |
| 10 | 9.1% | 30.8% | 0.18 | 0.67 |

**ระดับความเสี่ยงอธิบายได้** ต่ำคือต่ำกว่าอัตราผิดนัดเฉลี่ยของพอร์ต 8.07%
สูงคือถึงเกณฑ์ตัดสิน

| ระดับ | สัดส่วนผู้สมัคร | อัตราผิดนัดจริง |
|---|---:|---:|
| ต่ำ | 68.0% | 3.7% |
| ปานกลาง | 21.1% | 12.5% |
| สูง | 10.9% | 26.6% |

**ดัชนี 300–850 ยึดกับพอร์ตนี้ ไม่ใช่ FICO** คนที่ความเสี่ยงเท่าค่าเฉลี่ยพอร์ต
ได้ 600 ค่ากลางของผู้สมัครคือ 631 ช่วงที่ใช้จริงคือ 417 ถึง 848 ไม่มีค่าใด
ชนขอบ ห้ามนำไปเทียบกับคะแนนเครดิตบูโร

## ข้อจำกัดที่ต้องรู้ก่อนนำเสนอ

- **ตัดเพศออกแล้ว ช่องว่างระหว่างเพศยังไม่หายไปเอง** ผู้ชายในข้อมูลผิดนัดจริง
  10.3% ผู้หญิง 6.9% โมเดลตีธงผู้ชาย 15.0% ผู้หญิง 8.8% อัตราส่วนการตีธง
  1.70 เท่า สูงกว่าอัตราส่วนการผิดนัดจริงที่ 1.50 เท่า ส่วนหนึ่งมาจากตัวแปรอื่น
  ที่สัมพันธ์กับเพศ เช่นอาชีพ เรื่องนี้ต้องให้ผู้รู้ด้านกฎหมายและความเป็นธรรม
  ตัดสินว่ายอมรับได้หรือไม่
- **ไม่มีการทดสอบแบบ out-of-time** ข้อมูลไม่มีคอลัมน์วันที่ ผลอาจไม่คงที่
  เมื่อพฤติกรรมลูกค้าเปลี่ยนไปตามเวลา
- **คะแนนเครดิตภายนอกเป็นตัวแปรหลัก** สามช่อง EXT_SOURCE ต้องมาจากระบบจริง
  ที่เจ้าหน้าที่ดึงมา ถ้าค่าเหล่านี้ผิด คำตอบจะผิดตาม
- **ไฟล์ข้อมูลดิบหายไปแล้ว** ยังเทรนใหม่ได้จากข้อมูลที่ประมวลผลแล้ว
  แต่ประมวลผลจากข้อมูลดิบใหม่ไม่ได้ จนกว่าจะดาวน์โหลดจาก Kaggle อีกครั้ง

## ติดตั้งและใช้งาน

ต้องใช้ Python 3.10 ขึ้นไป

~~~powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
~~~

`requirements.txt` มีเฉพาะแพ็กเกจที่ระบบใช้จริง ถ้าต้องการรัน notebook เก่า
ให้ติดตั้ง `requirements-notebooks.txt` เพิ่ม

~~~powershell
python src/check_data_quality.py      # ตรวจคุณภาพข้อมูล
python src/model_training.py          # เทรนโมเดลใหม่ ราว 4 นาที
python src/inspect_model.py           # ดูข้อมูลโมเดลและฟีเจอร์สำคัญ
python -m streamlit run app/streamlit_app.py
pytest                                # 65 tests
~~~

ทุกครั้งที่เทรน ระบบจะบันทึก SHA-256 ของโมเดลไว้ข้างไฟล์ และตรวจก่อนโหลดทุกครั้ง
ไฟล์โมเดลเป็น pickle ซึ่งรันโค้ดได้ตอนโหลด จึงควรโหลดเฉพาะไฟล์จากแหล่งที่เชื่อถือได้

## โครงสร้าง

~~~text
app/streamlit_app.py       หน้าเว็บสำหรับเจ้าหน้าที่สินเชื่อ
src/model_training.py      เทรน calibrate ประเมิน และบันทึก bundle
src/inference.py           API ทำนายที่หน้าเว็บเรียกใช้ และการตรวจไฟล์โมเดล
src/feature_generation.py  สูตรฟีเจอร์ที่ใช้ร่วมกันทั้งตอนเทรนและตอนทำนาย
src/check_data_quality.py  ตรวจ schema, ID, target, sentinel และ infinity
src/data_preprocessing.py  รวมตารางข้อมูลดิบ ใช้ได้เมื่อมีไฟล์ใน data/raw
tests/                     unit tests และ end-to-end tests
notebooks/                 ประวัติการทดลองเดิม ตัวเลขในนั้นใช้อ้างอิงไม่ได้
~~~

Notebook เดิมทำ SMOTE ก่อนแบ่งข้อมูล ตัวเลขจึงสูงเกินจริงและห้ามนำมาอ้างอิง
